Exclusão, estados da tela e recuperação de erros

PONTO DE PARTIDA

Como estava antes

Marco 4
Lista e quadro com busca, filtros e mudança de status.
Estados já presentes
Havia mensagens de carregamento e alguns estados vazios.
Limitações
Faltava exclusão confirmada e uma recuperação consistente de erros e itens inexistentes.

O QUE FOI FEITO

Exclusão com confirmação

Antes de excluir
O cartão abre uma confirmação com opções de cancelar ou confirmar.
Na API
A função excluirTarefa envia DELETE e aceita respostas 200 ou 204.
Depois da resposta
A tarefa sai da tela somente após a API confirmar. Se falhar, aparece um aviso.

O QUE FOI FEITO

Carregamento e estados vazios

Carregando
A tela informa que está buscando os dados e identifica o estado para leitores de tela.
Sem dados
Há mensagens para lista vazia, projeto sem tarefas e busca sem resultados.
Aprimoramento da tarefa 34
A tarefa 34 (PR #72) esclarece o próximo passo e mantém os filtros acessíveis na lista vazia.

Os estados vazios já existiam parcialmente no Marco 4.

O QUE FOI FEITO

Falhas e dados inexistentes

Falha de consulta
A aplicação mostra uma mensagem e oferece “Tentar novamente” nas telas de consulta.
Item inexistente
A resposta 404 recebe uma mensagem específica de tarefa ou projeto não encontrado.
Falha ao salvar ou excluir
O usuário recebe um aviso. Na edição, os dados preenchidos permanecem no formulário.

POR DENTRO DO CÓDIGO

Como o Svelte organiza a tela

$state
Guarda valores que mudam, como carregando, erro e os dados da tarefa.
{#if ...} / {:else}
Escolhe a mensagem ou o conteúdo exibido conforme o estado atual.
try / catch / finally
A requisição tenta acessar a API, trata a falha e encerra o carregamento.

QUALIDADE

Acessibilidade e validação

Navegação por teclado
Diálogo com foco no botão de cancelar e retorno do foco após a ação.
Mensagens acessíveis
Uso de role="status" e role="alert", além de ajustes em títulos e regiões da página.
Auditoria registrada
Lighthouse de acessibilidade: 95 para 100 na lista local. Axe-core em 9 rotas a 320 px.

Resultados conforme docs/marco-5/auditoria.md, para os cenários avaliados.

RESULTADOS

Vantagens para o projeto

Menos exclusões acidentais
A confirmação permite cancelar antes do envio à API.
Situações mais claras
O usuário distingue espera, falha, ausência de dados e item inexistente.
Código mais sustentável
A API centraliza requisições e erros HTTP; componentes reaproveitam o fluxo de exclusão.

APRESENTAÇÃO

Demonstração sugerida

1. Busca sem resultado
Digite um título inexistente e limpe os filtros.
2. Exclusão
Crie uma tarefa de teste, abra a confirmação e mostre cancelar e excluir.
3. Recuperação
Com a API parada, mostre o erro. Religue a API e use “Tentar novamente”.
